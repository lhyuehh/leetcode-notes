001. 两数之和（简单）

一句话核心：暴力慢在内层每次线性找 target - x；用哈希表记住左边看过的 {值: 下标}，把内层查找降成 O(1)。

一、底层原理图解

  • 平均查找 O(1)：通过散列函数把 Key 直接算成底层数组下标，一步定位。
  • 最坏 O(n)（极罕见）：大量碰撞挤进同一槽位挂链表时退化；Python 内置随机化哈希与动态扩容，刷题直接按 O(1) 算。

二、下次遇到怎么想？（简单 3 步）

  1. 先写暴力，盯住内层循环：内层只是在问“左边有没有 target - x”，属于精准等值查询 → 立刻换哈希表。
  2. 套“枚举右，维护左”：
  3. 走到 j 时，向左边查：target - x in idx？
  4. 离开 j 时，把当前值留给右边：idx[x] = j。
  5. 检查边界：先查再存，天然不会自己配对；遇到重复数（如 [3, 3], target = 6）也是先查到前面的 3 直接返回，不会被覆盖。

三、我容易做错的地方

  • ❌ 先把所有元素一股脑塞进字典再查：容易把同一个下标用两次（自己加自己等于 target），还多了一次循环。
  • ✅ 正确做法：边遍历、边查询、再插入（先查后存）。
  • ❌ 把 下标 -> 值 存反了：我们需要通过“数值 target - x”反查“下标”，所以 Key 必须是数值，Value 才是下标。

四、标准代码（Python）

class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        idx = {}  # {数值: 下标}
        for j, x in enumerate(nums):
            if target - x in idx:
                return [idx[target - x], j]
            idx[x] = j
  • 时间复杂度：O(n)
  • 空间复杂度：O(n)
