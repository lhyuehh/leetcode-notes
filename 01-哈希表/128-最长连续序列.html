128. 最长连续序列（中等）

一句话核心：题目卡死 O(n) 不能排序；把数字丢进 set，只从“没有前驱 x - 1 的起点”开始往后数，每个数最多被数 1 次。

二、下次遇到怎么想？（简单 3 步）

  1. 看复杂度要求：要 O(n)，直接排除 O(n log n) 的排序，转向哈希表 O(1) 查邻居。
  2. 从暴力找重复：纯暴力枚举每个数往后数慢在两处——list 查找 O(n)，且同一段连续数字会被从中间反复数。

三、我容易做错的地方（重点避坑）

如果用自己推导的“端点合并法”，这 3 个坑最容易中招：

  1. ❌ 只更新紧邻的 x - 1 和 x + 1，忘了更新最远端点
  2. 比如 [3, 4] 插入 2，只改 table[3] 会让最右端 table[4] 停留在旧值，后面来 5 就会算错。
  3. ✅ 必须更新区间外边界：table[x - left] 和 table[x + right]。
  4. ❌ left == 0 时写 table[x - 1] = cur 导致“无中生有”
  5. 左边没有数时，把根本不在数组里的 x - 1 写进表里，会污染后续判断。
  6. ✅ 写成 table[x - left] 后，当 left == 0 时退化为 table[x]，不会造假数字。
  7. ❌ 两个 if 分开写，边读边改导致两侧长度不同步
  8. ✅ 严格遵守三段式：先全读 left, right → 再算 cur = left + 1 + right → 最后统一写三个端点。

实战建议：面试/冲刺时直接写 Set 起点剪枝法，代码只有 8 行，几乎不可能写错边界。

四、标准代码（Python）

解法一：Set 起点剪枝法（推荐）

class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        st = set(nums)
        ans = 0
        for x in st:
            if x - 1 not in st:  # 只从连续段起点出发
                y = x + 1
                while y in st:
                    y += 1
                ans = max(ans, y - x)
        return ans

解法二：端点合并法（一次遍历）

class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        table = {}
        maxlen = 0
        for x in nums:
            if x not in table:
                left = table.get(x - 1, 0)
                right = table.get(x + 1, 0)
                cur = left + 1 + right
                table[x] = table[x - left] = table[x + right] = cur
                maxlen = max(maxlen, cur)
        return maxlen
  • 时间复杂度：O(n)
  • 空间复杂度：O(n)

五、两种解法对比：空间与流式场景

对比维度 端点合并法（dict） Set 起点剪枝法（set）
底层与时间/空间 哈希表 O(1) 查询，时间 O(n) / 空间 O(n)（dict 存键值略占内存） 哈希表 O(1) 查询，时间 O(n) / 空间 O(n)（只存键更省内存）
